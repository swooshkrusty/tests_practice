A: n end deletions → O(n)
B: n tail removals → O(n)
Why both loops are linear / Почему оба цикла линейные

A: deleting the last Python list element is O(1) amortized. No later elements need to shift left. Across all n deletions, the total is O(n), including occasional backing-array shrink operations.

A: удаление последнего элемента Python list — O(1) амортизированно. Следующих элементов для сдвига нет. Все n удалений занимают O(n), включая возможные операции уменьшения внутреннего массива.

B: with a tail reference and previous links, removeLast() finds the previous node directly and updates a constant number of links: O(1). Repeating n times gives O(n).

B: при наличии tail и обратных ссылок removeLast() сразу находит предыдущий узел и меняет постоянное число ссылок: O(1). Повторяем n раз — получаем O(n).

Important assumptions / Важные условия

The linked list is doubly linked, maintains head and tail, and stores its size so getSize() is O(1). A singly linked list generally needs a traversal to find the node before tail, even when tail is stored.

Список именно двусвязный, хранит head, tail и размер, поэтому getSize() — O(1). Односвязному списку обычно нужен обход для поиска узла перед хвостом, даже если tail известен.

The small example uses 4 values. Synchronized steps explain the operations; they are not a performance benchmark. Actual speeds depend on implementation, allocation and other constant costs. The Python list diagram shows logical elements, not allocated capacity.

В примере 4 значения. Синхронные шаги объясняют операции, а не измеряют производительность. Реальное время зависит от реализации, выделения памяти и других постоянных затрат. На схеме Python list показаны логические элементы, а не выделенная ёмкость.
