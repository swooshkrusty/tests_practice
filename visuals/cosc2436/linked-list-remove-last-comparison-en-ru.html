Remove the last node: A vs BУдаление последнего узла: A и B

Two copies of the same singly linked list. Watch the extra search in A.

Две копии одного односвязного списка. Сравни дополнительные проходы в A.

A · get() + remove()

2 scans / 2 прохода
while len(list2) > 0:    list2.remove(list2.get(len(list2) - 1))

B · removeLast()

1 scan / 1 проход
while list2.getSize() > 0:    list2.removeLast()

Correct answer: code fragment B runs faster than A.Правильный ответ: фрагмент B работает быстрее A.

A first finds the last value, then searches again to remove it. B directly searches for the node before the tail and unlinks the tail.

A сначала находит последнее значение, затем снова ищет его для удаления. B сразу находит узел перед хвостом и удаляет хвост.

Why both are O(n²) / Почему оба — O(n²)

For a list of size m, get(m − 1) takes O(m), remove(value) takes O(m), and removeLast() takes O(m) in a typical singly linked list. A therefore does two linear searches per removal, while B does one. Repeating for sizes n, n − 1, …, 1 gives O(n²) for both. B avoids extra work; Big O hides constant factors.

При длине m операции get(m − 1), remove(value) и removeLast() в обычном односвязном списке требуют O(m). A делает два линейных поиска на удаление, B — один. Для длин n, n − 1, …, 1 получаем O(n²) в обоих случаях. B выполняет меньше работы; Big O не учитывает постоянные множители.

A tail pointer alone cannot give the previous node in a singly linked list. In a doubly linked list with a tail pointer, removeLast() can be O(1), making B O(n) overall.

Одного указателя tail недостаточно, чтобы найти предыдущий узел в односвязном списке. В двусвязном списке с tail операция removeLast() может быть O(1), а весь B — O(n).

Example assumptions / Условия примера

The animation uses unique values [10, 20, 30, 40], cached O(1) size, and remove(value) that searches from head while keeping track of the previous node. With duplicates, remove(lastValue) may remove an earlier matching node instead of the tail. Actual work depends on the LinkedList implementation.

В анимации уникальные значения [10, 20, 30, 40], размер хранится отдельно и доступен за O(1), а remove(value) ищет от head, запоминая предыдущий узел. При повторах remove(lastValue) может удалить более ранний узел с тем же значением вместо хвоста. Реальные затраты зависят от реализации LinkedList.
