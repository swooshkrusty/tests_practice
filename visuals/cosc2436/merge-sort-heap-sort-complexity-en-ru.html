Correct answer: O(nlogn).Правильный ответ: O(nlogn).

Merge sort: O(log n) merge levels × O(n) work per level.

Merge sort: O(log n) уровней слияния × O(n) работы на уровень.

Heap sort: O(n) heap construction + O(n) extractions × O(log n) heap repair.

Heap sort: O(n) на построение кучи + O(n) извлечений × O(log n) на восстановление.

Merge sort → O(n log n)
Heap sort → O(n log n)
Why this is a worst-case bound / Почему это оценка худшего случая

Merge sort keeps splitting into halves regardless of input order. At each merge level, all n elements are processed across the groups. There are about log₂ n such levels. The animation shows whole merge levels, not individual comparisons.

Merge sort делит список пополам независимо от порядка данных. На каждом уровне слияния во всех группах суммарно обрабатываются n элементов. Таких уровней около log₂ n. Анимация показывает целые уровни, а не отдельные сравнения.

A binary heap has height O(log n). After moving its maximum to the sorted suffix, sift-down follows at most one root-to-leaf path. With n − 1 extractions, the total is O(n log n). Some repairs stop earlier; not every extraction takes exactly log₂ n steps.

Высота двоичной кучи — O(log n). После переноса максимума в отсортированный суффикс просеивание вниз проходит не более одного пути от корня к листу. Для n − 1 извлечений получаем O(n log n). Иногда восстановление заканчивается раньше; не каждое извлечение занимает ровно log₂ n шагов.

For n = 8, merge sort has 3 merge levels. The value 8 × 3 = 24 illustrates element processing across those levels; it is not an exact comparison count for both algorithms.

При n = 8 у merge sort 3 уровня слияния. Число 8 × 3 = 24 иллюстрирует обработку элементов на этих уровнях; это не точное число сравнений для обеих сортировок.
